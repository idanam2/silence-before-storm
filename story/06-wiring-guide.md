## מצב שצריך להוסיף ל-`G.state` (ולשמירה)
```js
G.state.story = {
  flags: {},            // id -> true/value
  quests: {},           // id -> { status: 'active'|'done', step: index, counters: { stepId: n } }
  played: {},           // dialogue id -> true (בוחרי השיחה ודיאלוגים חד-פעמיים)
  read: {},             // note id -> true
  spotsUsed: {},        // spot id -> true (ל-once)
  fired: {},            // trigger id -> true (ל-once)
  events: {},           // story event id -> count
  unlocked: ['forest'], // יעדים במפה (כל השאר מוסתרים עד unlock)
  chapter: 0,           // הפרק הנוכחי = chapter של המשימה הראשית הפעילה
  weather: 'clear'
};
```
להעלות `VERSION` ב-`js/save.js` ולהוסיף מיגרציה (שמירה ישנה = `story` ריק + `unlocked` = כל היעדים, כדי לא לנעול שחקן קיים).
`sanitize`: לסנן דגלים/משימות לא מוכרים לפי `storyFlags` / `storyQuests`.

## מודולים מומלצים (טהורים, נבדקים ב-Node)
1. **`js/story.js`** — מנוע: `emit(event, data)`, `run(actions)`, `reqOk(req)`, התקדמות משימות לפי סוגי הצעדים
   (רשימה בראש `quests.js`), טריגרים, בוחרי שיחה. בלי DOM. מחזיר רשימת "בקשות תצוגה" (פתח דיאלוג, הצג פתק, toast).
2. **`js/dialogue.js`** — מצב דיאלוג: צומת נוכחי, שורה נוכחית, בחירות זמינות (`req` שלא מתקיים = **מוסתר**, לא אפור).
   `auto: true` בצומת = לבחור אוטומטית את הבחירה הראשונה שמתקיימת (משמש את `dlg_rachel_idle`).
3. **`js/dialogueui.js`** — חלונית DOM: תחתית המסך, RTL, שם דובר בצבע (`storySpeakers`), לחיצה/E/רווח = הבא, 1-4 = בחירה.
   סגנון לפי `mode`: `thought` נטוי בלי מסגרת, `radio` עם רעש (`static` = עוצמת אפקט חזותי עדין + רעש לבן בשמע), `slate` כתב יד על רקע גיר,
   `recording` עם אייקון קלטת, `system` אפור במרכז. **בלי הבהובים ובלי קפיצות** (CLAUDE.md).
   התנועה והזמן קפואים בזמן דיאלוג (כמו בחלוניות).
4. **`js/journal.js`** — מקש J: משימה ראשית + צעד נוכחי, משימות צד פעילות (בלי `hidden`), פתקים שנקראו לפי `series`.

## נקודות (`storySpots`)
- `area` + `hint` אומרים איפה; את ה-x,y המדויק קובע מי שבונה את המפה (להוסיף שדה `at: {x,y}` לכל נקודה, או מערך `spots` באזור ב-`data/areas.js`).
- `isNew: true` = האובייקט לא קיים במפה (לצייר: פעמוני רוח, כוורות, מחנה, ארונות חשמל, דלת הפלדה, וכו').
- `kind: 'relay'`: החזקת E, רעש קבוע `noise` (דרך `G.data.noise` / שמיעת אויבים), גל `wave` אחרי חצי מהזמן מקצוות האזור, `relay_built` בסוף.
- `kind: 'listen'`: לעמוד בתוך `r` בלי לזוז `hold` שניות (בלי מקש). מתאים לרגעים שקטים.
- `kind: 'npc'`: דמות עומדת (רחל, אורי). אפשר לצייר עם `G.player.create` + פלטה משלה (כמו אויבים), בלי AI.
- `req` לא מתקיים: הנקודה מוסתרת, חוץ מאם יש `deny` (אז מוצגת, ו-E מראה את הטקסט).

## אזורים חדשים (`storyNewAreas`)
`eitan_house`, `ship_bridge`, `tower_top`, `lab_tunnel`, `lab_main`. כולם `interior: true` עם `parent`, באותו מנגנון של `data/interiors.js`.

## דברים קטנים שצריך במנוע
- **מפה נעולה:** בתחילת משחק חדש רק היער פתוח; `unlock` פותח יעד (המפה כבר מציירת את כולם; להסתיר סמן ומסלול).
- **פריטי מפתח:** `key: true` לא אובדים במוות, לא נצרכים ב-"use", ו-`sanitize` לא מוחק אותם.
- **מזג אוויר:** `storm` = גשם (חלקיקים), עמעום, רוח בשמע, ושמיעת אויבים ×0.5 (`G.data.noise`). רק אחרי פרק 8.
- **פעמוני רוח בחווה:** עד שכולם נלקחו, רעש קבוע מכל פעמון (כמו `noise` של נקודה), כדי שהשחקן יבין למה הם מסוכנים.
- **אור הרדיו:** `radio: on` מדליק נורית ירוקה על `spot_home_radio` כשיש שיחה ממתינה בתור.
- **`motif` / `hum`:** שורה עם `motif: true` מנגנת את ארבעת הצלילים (להוסיף ל-`js/sfx.js`: 4 טונים רכים, השלישי הכי גבוה, הרביעי נשאר תלוי;
  אחרי `noa_answered` הגרסה עם רביעי שיורד). `hum: true` = אותו מוטיב בגוון של זמזום (סינוס עם ויברטו קל).
- **הקשת:** הדגל `unlock_bow` וחלקי `bow_parts` מחכים לפריט קשת (לפי CLAUDE.md: פרק 2).
- **האלה:** `unlock_club` נקבע בפרק 1. המתכון כבר קיים ב-`data/recipes.js`; אפשר להסתיר אותו עד הדגל.
- **ציוד התחלתי:** כשהסיפור מחובר, להחזיר את `G.data.inventory.start` לגרזן + אוכל + מים בלבד (האקדח והמתכות הזמניות יוצאים),
  כי הנשקים מגיעים מהסיפור (משטרה, בסיס צבאי) ומהשכונה.

## סדר מימוש מומלץ
1. מנוע + שמירה + חלונית דיאלוג + יומן (בלי תוכן): בדיקות Node.
2. פרולוג + פרק 1 (בית, יער, חווה, רחל): זה סקופ "שלב 7" ב-CLAUDE.md.
3. פרק 2 (שכונה + בית 7 + ממסר) = "שלב 8".
4. כל פרק אחר בשרשור משלו: נקודות במפה, אזור חדש אם יש, ואז הנתונים כבר מוכנים.
5. הסיום (מנהרה, מעבדה, סופים) אחרון.

## בדיקות מוצעות (`tests/`)
- כל פרק אפשר לסיים: סימולציה שמריצה את האירועים לפי הסדר ובודקת שהמשימה הבאה נפתחה.
- הסוף השלישי מוצג רק עם ארבעת הדגלים; סוף א' וב' תמיד.
- שמירה וטעינה באמצע פרק שומרות צעד, מונים ודגלים.
- `node story/check.js` כחלק מ-`tests/run.js`.
